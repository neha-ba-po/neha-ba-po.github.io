01 · ENERGY UTILITIESGRID FEE HUB

From German energy rules to executable pricing behaviour.

A complex integration topic where market-location data, pricing rules, fallback behaviour and billing handoff had to work reliably across connected platforms.

Challenge

Translate German utility rules and market communication requirements into precise system behaviour across PACS, CPQ and Billing.

My contribution

Owned the CPQ-side requirements and flow: API behaviour, business rules, fallback logic, article IDs, prices, error handling, acceptance criteria, SQL validation and testing.

Outcome

A traceable requirements baseline connecting regulation, data flows, API behaviour and downstream billing inputs, while reducing repeated third-party API calls.

3CPQ decisionApply prices & article IDs

MAPPED

When UTILMD mapping is available, CPQ uses the response to apply relevant KWK, Offshore, interruptible and concession-fee article IDs/prices before returning the required response to Billing.

FALLBACK

If mapping data is unavailable, CPQ checks whether product fallback is enabled. When enabled, it retrieves fallback values from PACS price-sheet/PRICAT data.

CONTROLLED FAILURE

If fallback is not enabled, CPQ returns defined error codes and Billing can surface the corresponding user-facing message.

Scope boundary: Billing's own formula/calculation process is outside the CPQ-side feature scope.
